## Что нашлось

Пересборка и не могла ничего изменить: сайт отдаётся не из `main`.

```
$ gh api repos/vi-k/flutter_curves/pages
"build_type": "legacy"
"source": {"branch": "gh-pages", "path": "/"}

$ git log -1 --format=%ci origin/gh-pages
2023-10-23 23:19:48

$ curl -sI https://yet-another.dev/ | grep last-modified
last-modified: Mon, 23 Oct 2023 23:20:17 GMT
```

Публикация идёт **с ветки `gh-pages`**, а её последний коммит — октябрь
2023 года. Workflow в репозитории нет, ветку никто не обновлял, поэтому
вся работа 2026-09-11 и 2026-09-12 в `main` до сайта не доходила.

Белый экран — следствие того же. В `index.html` той сборки стоит

```html
<base href="/flutter_curves/">
```

потому что тогда приложение жило по адресу
`vi-k.github.io/flutter_curves/`. С apex-домена каждый ресурс ищется на
уровень глубже, чем лежит, и страница загружается пустой.

## Что сделано

**`web/CNAME`.** Домен лежал файлом только на `gh-pages`; публикация с
ветки читает `CNAME` из выложенного дерева, так что первый же деплой без
него снёс бы домен. Теперь файл лежит в `web/`, Flutter копирует его в
`build/web`, и потерять домен деплоем больше нельзя.

**Пересборка и выкладка.**

```sh
flutter build web --wasm --base-href /   # ✓ Built build/web
```

`build/web` целиком заменил содержимое `gh-pages`. Проверено после
деплоя:

| Что | Ответ |
| --- | --- |
| `/` | 200, `<base href="/">`, `src="flutter_bootstrap.js"` |
| `/flutter_bootstrap.js` | 200, 13 295 |
| `/main.dart.wasm` | 200, 1 862 627 |
| `/canvaskit/skwasm.wasm` | 200, 3 593 521 |
| `/CNAME` | 404 — Pages забирает его себе как настройку |

Приложение поднято в браузере: график рисуется, моушены идут, слайдеры
двигают кривую. В консоли одно предупреждение — skwasm просит
`Cross-Origin-Opener-Policy` и `Cross-Origin-Embedder-Policy` ради
многопоточности и без них работает в один поток. Заголовками GitHub Pages
не управляет, а ставить их тут и не надо: под изоляцией эта сборка даёт
белый экран, см. `2026-09-12[2]-web-bootstrap-report.md`.

**`https_enforced`.** Был `false`, стал `true`; `http://yet-another.dev/`
отвечает 301. Сертификат на `yet-another.dev` и `www.yet-another.dev`
действует до 2026-11-28 и выпускается GitHub'ом сам.

## Почему деплой пока ручной

Напрашивается workflow, который собирает и выкладывает на каждый пуш в
`main` — тогда «в `main` новое, на сайте старое» стало бы невозможно. Он
здесь не заводится по одной причине:

```yaml
# pubspec.yaml
auto_scroll_band:
  path: ../auto_scroll_band
```

Сосед лежит в **приватном** репозитории `vi-k/auto_scroll_band`, а
`GITHUB_TOKEN` внутри Actions видит только свой репозиторий. Runner не
сможет его выкачать, `pub get` упадёт — тот же самый путь, который уже
останавливал проект на три года, теперь останавливает и CI.

Развязок три, и все требуют решения владельца:

| Развязка | Цена |
| --- | --- |
| Открыть `vi-k/auto_scroll_band` | Чужой репозиторий станет публичным |
| Секрет с PAT | Токен к приватному коду — в публичном репозитории |
| Издать `auto_scroll_band` на pub.dev | Поднять ему пол SDK и выпустить |

До тех пор деплой — это `flutter build web --wasm --base-href /` и
выкладка `build/web` в `gh-pages`.

## Развязка

Владелец выбрал первую: `vi-k/auto_scroll_band` открыт в тот же день.
Перед открытием история просканирована — ключей, токенов и паролей нет, —
и из неё убрана рабочая почта `nashol@yandex-team.ru`: оба коммита
переписаны на личную, даты и содержимое сохранены. Осиротевший коммит
`dd53489` на GitHub какое-то время ещё достаётся по полному SHA: чужих
объектов сервис не собирает по требованию.

Дальше заведён `.github/workflows/pages.yml` — сборка и деплой на пуш в
`main`. Две вещи в нём стоят комментария и получили его:

- runner выкачивает **два** репозитория в соседние папки, иначе путь
  `../auto_scroll_band` из `pubspec.yaml` никуда не ведёт;
- `--base-href /` повторяет то, ради чего написана вся эта запись.

Публикация при этом переезжает с ветки на Actions, а значит `CNAME`
перестаёт работать файлом и становится настройкой Pages — ровно так же,
как в соседнем репозитории `vi-k/solo`. Что осталось сделать руками,
записано в `docs/handoff.md`, раздел «Сайт».
